## Now — foundations (isolated, dependency-free; complete + trust the graph before building analytics on it)

- **Graph/pivot/export correctness property tests** — Hypothesis properties over `structure_topologies()` asserting pathfinder soundness (every returned path is a real walk with correct endpoints, no repeats, true BFS length in shortest mode), graph-build correctness, and export→import round-trip fidelity. New coverage over the pivot engine specifically — the correctness net the Phase-2 pathfinding work builds on. Do first.
- **Referential-integrity validation (server-side)** — reject writes that break integrity: a connection's src/dst hosts must belong to the op, a credential-link's `host_user` must belong to the host; infer/normalize `addr_type` server-side instead of trusting the `ipv4` default. The API is the real surface (CLI + scripts), so these can't be client-only. Cosmetic/confirm-dialog validation stays client-side — out of scope here.
- **Fix wtmp/lastlog binary struct** — the record format calcsizes to 382 bytes but real glibc `struct utmp` is 384 (2-byte pad after `ut_type`), so every record after the first misaligns and wtmp/btmp yield ~zero `ConnectionRecords` on 64-bit Linux. Fix the layout, add the `ut_addr_v6` IPv6 path, apply the same to lastlog. Unlocks a whole confirmed inbound-login evidence class; regen the `real_examples` snapshots.
- **Parse authorized_keys `from=`/`command=` options** — `AuthorizedKeysParser` strips the options prefix today, discarding `from="IP/CIDR"` (a host-authored ACL naming exactly which source may use a key — top-tier pivot signal), `command=`, `restrict`, `no-pty`. Emit them (indicator-tier evidence).
- **Shell-history inline credential & endpoint mining** — extend the bash/zsh/fish history parsers (today SSH-destinations only, via the shared `_SSH_RE`) to also mine inline secrets and non-SSH pivot endpoints, reusing the `ps_output` secret-regex library.
- **Deepen auth.log parser** — infer the missing syslog year (fixes mis-dated edges), extract `sudo`/`su` privesc lines (seeds the Phase-2 sudo-aware paths), and run the same Accepted-login extraction over `journalctl -u ssh` text output so systemd-only hosts aren't blind. Failed-auth / negative-evidence deliberately out of scope; no `outcome` column.

## Next — analytics engine (reads the completed graph; dependency-ordered)

- **Confidence semantics + pathfinding weighting** — make confidence mean "you can log in *right now*": downgrade `key_match` on encrypted-no-passphrase or public-key-only credentials, attach a `usable`/`needs_passphrase`/`needs_crack` flag, and weight `find_paths` by confidence so it prefers executable hops and never routes through indicator-only edges. The semantic foundation the queries below trust. After: correctness property tests (Now).
- **Single-source reachability & blast-radius** — one-call transitive closure over the pivot DiGraph: from a host, every reachable host with its shortest path, hop count, and weakest-link confidence; symmetrically, what a credential/fingerprint unlocks, ranked (crown-jewel keys). "Reach from here" / N-hop isolate node action + next-hop copy-command cards. **Supersedes the standalone credential blast-radius rollup.** After: confidence semantics.
- **Objective/target board** — inverts the pathfinder: tag hosts `status=target`, then across all footholds compute the best route *into* each target (ranked by weakest link) and the specific missing hop/credential blocking it when no path completes. After: reachability + confidence.
- **Sudo / user-aware pivot paths** — rebuild pathfinding over `(host, username)` states so a chain is only returned when every hop chains at the user level, with NOPASSWD sudo bridging same-host privilege steps. ⚠ Requires revising Architecture Rule #17 (sudo is informational-only today) — ship the additive sudo-escalation-evidence slice first and confirm the rule change before the traversal rewrite; make it downgrade confidence, never hard-suppress. After: deepen auth.log (sudo lines) + reachability.

## Later — heavy features + independent

- **Parser Workbench** — new top-level `/parsers` page (outside any op). Minimal catalog (registry types + collection command + "try it") behind a new `GET /parsers`; multi-file sandbox + paste-text with per-file type auto-detect (content-sniff + `<file_type>__<user>.<ext>` convention) and per-row override; **tier-1** parser-only preview (`POST /parsers/preview`, no DB); **tier-2** dry-run against a target op + one source host via `process_single_file(dry_run=True)` + rollback; import commits the batch through the existing upload path. Adds a `dry_run` flag to `process_single_file` that skips the raw-file write (Rule #20 note). Absorbs the pre-upload dry-run and the full-file-type-list + content-sniffing ideas.
- **Engagement report export** — `GET /ops/{op_id}/report?format=markdown|html`: structured engagement summary (op metadata, host inventory, credential inventory, pivot paths via `find_paths`, sudo escalation summary, activity timeline). Markdown primary; HTML wraps it in a minimal printable template. Full credential values are shown — Lockpick never redacts, including in reports (intentional for the trusted single-operator deployment). After: reachability + confidence (consumes the pivot chains).
- **Op summary + briefing fields** — Operation gains two markdown fields: `summary` (short, rendered in op header) and `briefing` (long, collapsible in op detail view). Both user-editable, optional. Requires two new columns + an Alembic migration. Independent.
