## Now — foundations (isolated, dependency-free; complete + trust the graph before building analytics on it)

- **Referential-integrity validation (server-side)** — close three verified gaps: `create_connection` assigns `src_host_id`/`dst_host_id` with no op-membership check (`routers/connections.py`); `create_credential_link` doesn't verify `host_user_id` belongs to the host (`routers/credentials.py`); `add_host_ip` trusts the `ipv4` default (`schemas.py` `HostIPCreate`) instead of inferring `addr_type` from the value. This *adds to* existing partial checks (credential-link already validates host-exists + cred/host same-op; connection-create validates credential-in-op) — it's the missing gaps, not validation from scratch. The API is the real surface (CLI + scripts), so these can't be client-only. Cosmetic/confirm-dialog validation stays client-side — out of scope here.
- **Parse authorized_keys `from=`/`command=` options** — `AuthorizedKeysParser` strips the options prefix today, discarding `from="…"` (a host-authored ACL naming which source may use a key — top-tier pivot signal), `command=`, `restrict`, `no-pty`. Emit the ACL as an indicator edge (`src`=the `from` value, `dst`=`__upload_host__`), which means extending `_INDICATOR_PARSER_TYPES` **and** the `EvidenceItem.type` Literal in lockstep (Rule #25). ⚠ Only a literal single IP maps to a host edge: `resolve_ip` rejects a CIDR (→ dangling record), and wildcard/negation forms (`*.corp.net,!jump`) are `SshConfigPattern` territory (Rule #14), not concrete hosts — decide how to represent those. `command=`/`restrict`/`no-pty` are key annotations with **no carrier field** in any dataclass — representation TBD. Effort M (the design calls, not the parser tweak, dominate).
- **Shell-history inline credential & endpoint mining** — extend the bash/zsh/fish history parsers (today SSH-destinations only; each defines its own regex — only bash uses `_SSH_RE`, zsh/fish use `_SSH_CMD_RE` + a destination walker) to also mine inline secrets and non-SSH pivot endpoints. The secret regexes are **private** constants in `ps_output.py` (`_SECRET_PATTERNS`, `_DB_URL_RE`), not a shared module — reuse means importing private symbols (parser coupling) or extracting a shared module (churns `ps_output` snapshots). The non-SSH-endpoint half is net-new (`ps_output` only extracts SSH-family endpoints; its DB-URL regex discards the host). Effort M.
- **Deepen auth.log parser** — now-doable & independent: make the syslog-year fallback robust (it already exists but is a naive `datetime.now().year`, mis-dating prior-year / year-boundary logs → fixes mis-dated edges), and add `journalctl -u ssh` coverage (that text already parses via the existing Accepted extraction — syslog-shaped, contains `sshd` — so it's mostly a fixture/test gap, not new parsing). ⚠ The `sudo`/`su` privesc extraction that used to headline this is **not** parser-only or independent — extracted events have no persistence target (`SudoRule` is read-only, Rule #17; `ConnectionRecord` models connections not escalations), so it belongs with the blocked *Sudo / user-aware pivot paths* item + its Rule #17 revision. Failed-auth / negative-evidence deliberately out of scope; no `outcome` column.

## Next — analytics engine (reads the completed graph; dependency-ordered)

- **Confidence semantics + pathfinding weighting** — make confidence mean "you can log in *right now*": downgrade `key_match` on encrypted-no-passphrase or public-key-only credentials, attach a `usable`/`needs_passphrase`/`needs_crack` flag, and weight `find_paths` by confidence so it prefers executable hops and never routes through indicator-only edges. The semantic foundation the queries below trust. ⚠ Weighting invalidates the unweighted-BFS-optimality assertion in `tests/test_invariants/test_pivot_soundness.py` (`test_shortest_mode_is_bfs_optimal`) — rewrite it to compare against the weighted shortest distance in the same change.
- **Single-source reachability & blast-radius** — one-call transitive closure over the pivot DiGraph: from a host, every reachable host with its shortest path, hop count, and weakest-link confidence; symmetrically, what a credential/fingerprint unlocks, ranked (crown-jewel keys). "Reach from here" / N-hop isolate node action + next-hop copy-command cards. **Supersedes the standalone credential blast-radius rollup.** After: confidence semantics.
- **Objective/target board** — inverts the pathfinder: tag hosts `status=target`, then across all footholds compute the best route *into* each target (ranked by weakest link) and the specific missing hop/credential blocking it when no path completes. After: reachability + confidence.
- **Sudo / user-aware pivot paths** — rebuild pathfinding over `(host, username)` states so a chain is only returned when every hop chains at the user level, with NOPASSWD sudo bridging same-host privilege steps. ⚠ Requires revising Architecture Rule #17 (sudo is informational-only today) — ship the additive sudo-escalation-evidence slice first (the `sudo`/`su` parsing formerly under *Deepen auth.log* lives here — it needs this item's persistence target) and confirm the rule change before the traversal rewrite; make it downgrade confidence, never hard-suppress. After: reachability.

## Later — heavy features + independent

- **Parser Workbench** — new top-level `/parsers` page (outside any op). Minimal catalog (registry types + collection command + "try it") behind a new `GET /parsers`; multi-file sandbox + paste-text with per-file type auto-detect (content-sniff + `<file_type>__<user>.<ext>` convention) and per-row override; **tier-1** parser-only preview (`POST /parsers/preview`, no DB); **tier-2** dry-run against a target op + one source host via `process_single_file(dry_run=True)` + rollback; import commits the batch through the existing upload path. Adds a `dry_run` flag to `process_single_file` that skips the raw-file write (Rule #20 note). Absorbs the pre-upload dry-run and the full-file-type-list + content-sniffing ideas.
- **Engagement report export** — `GET /ops/{op_id}/report?format=markdown|html`: structured engagement summary (op metadata, host inventory, credential inventory, pivot paths via `find_paths`, sudo escalation summary, activity timeline). Markdown primary; HTML wraps it in a minimal printable template. Full credential values are shown — Lockpick never redacts, including in reports (intentional for the trusted single-operator deployment). After: reachability + confidence (consumes the pivot chains).
- **Op summary + briefing fields** — Operation gains two markdown fields: `summary` (short, rendered in op header) and `briefing` (long, collapsible in op detail view). Both user-editable, optional. Requires two new columns + an Alembic migration. Independent.
